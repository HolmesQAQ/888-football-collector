888 足球数据采集器｜第一阶段
规则依据：RULE_PROFILE_888_JCZQ-v2.1；A_PRE_SCRIPT_ODDS_HF2；EvidencePackage v2。

一、启动
双击“start.bat”，浏览器将打开本机界面。程序仅监听127.0.0.1。
本机优先使用Codex已自带的Python。其他电脑需要Python 3.10+；不需要pip安装任何依赖。
运行窗口要保持开启，结束时关闭该窗口或按Ctrl+C。每次启动端口和本机会话链接会变化。
本文件夹是唯一保留的888专用最新版，启动入口统一为start.bat。
历史采集报告保存在data目录；tests/fixtures包含2026-09-30回归样本，不是当天实时数据。

二、采集
1. 选择北京时间销售日；实际开赛日可能跨到次日。
2. 选择500、澳客或两站。
3. 点击开始。停止按钮会保留本轮已取得结果，当前请求最多等待约25秒。
4. 完成后打开本轮报告，可下载JSON、CSV和质量报告。
5. 补查时重新执行同一销售日，新运行不会覆盖旧快照；当前版本不自动合并旧赔率。

三、实测限制（2026-10-03）
500已接通公开混合过关页在线采集。按用户明确要求，robots提示记录为ROBOTS_NOTICE，不再作为此指定公开路径的硬拦截。
只使用普通GET，不登录、不伪造验证Cookie；真正收到403、429或验证页时仍停止。
2026-09-30在线验收取得2场比赛，每场五玩法54项，共108项赔率。此次为实时下载历史页面，不是导入样本。
仍支持导入自己保存的500混合过关HTML；导入不访问对应网站。
按用户提供的信息，2026-10-01至2026-10-04为体彩休市区间：在线任务标记MARKET_CLOSED，不请求销售页，不当作抓取故障。
休市区间保存在market_calendar.json，注明USER_PROVIDED来源；不自动套用于其他年份。
其他日期仍严格检查源站销售日，旧日期响应记录DATE_MISMATCH；未知空页不能据此断言全天没有比赛。
历史日期目前按站点日期页面读取；源站不支持或返回日期不符时记录失败，不假装支持。
历史页面可能已经包含赛后最终值；不能用现在读取的历史赔率证明当时赛前可得信息。

四、本地文件导入
窗口展开“本地页面导入”，填写500 HTML完整路径，或澳客文件目录。
澳客目录约定：okooo.html为目标销售日列表，okooo-more-3001.html等为该列表比赛编号对应的更多玩法HTML。
从真实公开页面取得的回归样本位于tests/fixtures，对应销售日2026-09-30。
离线验证示例（在程序目录执行）：
python collector.py --date 2026-09-30 --import-500 tests/fixtures/500.html --import-okooo tests/fixtures
本地导入记录导入时间，原抓取时间未知；不得视作当前销售核验。

五、数据内容
五玩法：SPF胜平负3项；RQSPF让球胜平负3项；JQS总进球8项（0至6、7+）；BQC半全场9项；BF比分31项。共54项。
保留源站ID、销售日、竞彩编号、球队、赛事、开赛时间、主队让球、场次/玩法销售状态及原始属性。
每个赔率项保留页面显示值、属性值、采用值、状态、来源、采集时间；来源未提供报价时点时quoted_at保持null。
澳客已截止时data-sp=0不代表页面显示赔率为0；程序独立读取显示值。
半全场按文字标签配对，不能按页面索引顺序机械映射。
来源值冲突不平均、不覆盖；没有合法数值时保留null。
跨站同场核对需日期、编号、主客队、赛事、开赛时间均符合；姓名别名不自动猜测。
没有已核别名时保留NEEDS_REVIEW，两站原记录独立保存。
即使两站一致，也不等于独立官方核验。

六、归档
data/archive.sqlite3：本地数据库，多轮累积。
data/运行ID/raw/：原始响应及robots响应，附哈希。
snapshot.json：本轮完整数据与质量状态。
odds.csv：UTF-8 BOM格式，每场每来源54行，适合Excel查看。
quality.json：来源失败、身份核对、差异和结构校验。
report.html：离线也能打开的可读报告，不执行源站脚本。
manifest.json：文件校验哈希。
可执行 python verify.py data/运行ID 检查归档完整性。哈希用于检测意外修改，不是第三方数字签名。
不要打开raw HTML执行源站脚本来查看报告；使用程序生成的report.html。

七、阶段边界
当前交付的是“赔率观察快照”，不是已冻结的EvidencePackage，不做方向分析、评级、组票、投注或Notion写入。
24维字段已预留；未采集维度为NOT_ATTEMPTED，evidence_status=null，coverage_integrity=INCOMPLETE。
这是本地草稿状态，不冒充规则要求的五种合法Coverage结论。只有后续真实补查后才能进入正式Evidence校验。
尚未实现亚盘/欧赔时序、战绩、伤停、阵容、天气、战术等基本面以及赛后结果采集。
SQLite已预留事实与赛果表。球队别名可通过命令行--aliases读取JSON，需按联赛提供names、canonical和evidence_url；不自动修改数据库映射。
示例结构：[{"league":"明确赛事名","names":["来源名A","来源名B"],"canonical":"核实后的身份","evidence_url":"证明两个名字同队的来源链接"}]

八、命令行与测试
python collector.py --date 2026-10-03 --source both
python collector.py --date 2026-09-30 --source okooo
python app.py
python -m unittest discover -s tests -v
命令行退出0仅表示采集层未发现列出的质量问题，不等于官方核验或分析可用；退出2为待核对/未取得/停止；其他未处理错误为退出1。

九、比分与来源数量（2026-10-03 更新）
澳客已接入本网站竞彩页的比分及赛果结算标记，统一输出完赛状态、90分钟比分、五玩法结果、半场胜平负与缺项原因；半场精确比分没有源站证据时保留空值。销售截止本身不会被判定为完赛，结算标记冲突时标为赛果冲突。
报告按来源显示实际比赛数和赔率值数量；PARSED 不是“数据为零”，请查看数量及逐场赔率。
在线采集500时，另读取对应销售日的公开比分页，按500比赛ID关联完赛状态、半场、90分钟比分及五玩法实际结果。
加时和点球保留为说明，不计入90分钟赛果。比分未取得、日期不符、比赛未完赛时不猜测最终比分。
比分来源仍为单站观察，未独立官方核验；不会因球队别名或竞彩编号相似而自动复制到澳客记录。
赛果保存于 snapshot.json、results.csv 和本地数据库；报告可直接下载赛果CSV。
历史归档不自动改写；请重新采集以生成带赛果的新报告。修改程序后需重新打开 start.bat 以加载新版后端。
